What Improved

All 11 games boot-verified The extended smoke harness booted every available recipe to readiness on real Docker, exercised each in-app console via a probe command, and verified expected config paths — including the heavy steamcmd titles (Rust, ARK, CS2, ARK: Survival Ascended).
In-app console for every supported game Recipe-driven console transports: Source RCON (Minecraft Java, CS2, ARK, ASA, Project Zomboid) and container-exec (Bedrock, Rust, Palworld), with per-game quick commands.
Campaign fixes landed The readiness watcher survives bootstrap container restarts, Source RCON follows the Valve spec, deletes remove root-owned volume files, and the stale Rust/CS2 images plus wrong ARK/Rust readiness patterns were corrected.
Config & file management UI Recipe-declared config files render as typed forms with raw-edit fallback; managed file tabs (mods, saves, plugins) support drag-drop upload; a new default install location setting prefills the create wizard.
Code review hardening An external review pass (17 findings) was fully addressed: volume cleanup path guards, symlink-escape fixes in file writes, exec timeouts, and safer Windows WSL diagnostics.
Major UI overhaul The desktop app moved to the Console-inspired redesign with updated dashboard, cards, detail views, onboarding, and shared UI components.
Automated checks passing Rust tests/clippy (deny warnings), frontend check/test/build, and website check/build are all green on CI for the release branch.
Version metadata aligned App package metadata, Tauri config, changelog, website package version, release docs, and audit manifest agree on v0.2.0.

Remaining Gaps

Windows validation pending The onboarding fix still needs real Windows acceptance testing across WSL disabled, reboot required, Docker installed but stopped, and post-Docker server creation scenarios.
macOS marked experimental Release CI builds macOS ARM and Intel artifacts, but the website intentionally routes macOS users to GitHub Releases until those builds are manually tested.
Two recipes track a rolling tag by necessity Rust force-updates monthly and moves its glibc floor, so only latest keeps working; Motor Town's image publishes no other tag. Both are documented, test-enforced exceptions (ROLLING_TAG_EXCEPTIONS) rather than policy drift.
Motor Town ships as Coming Soon Its dedicated server requires an owning Steam account plus interactive Steam Guard — incompatible with one-click hosting today. The recipe and art are in place to flip when a credential-less install path exists.
Vite/Node warning remains The website build passes but still emits a Node module.register() deprecation warning from the toolchain.
